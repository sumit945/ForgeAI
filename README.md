# ForgeAI - the agent that builds (and tests) agents

Give ForgeAI **one paragraph** and **a folder of documents**. It interviews the requester, checks that the documents can
actually support the request, generates a declarative agent, generates its own test set *from the documents*, judges the
agent, diagnoses every failure and applies targeted fixes (max 3 iterations), then hands back the agent **and an honest report**.

Everything runs on a small local open model (`qwen2.5:3b-instruct` via Ollama - fits a 4 GB GPU) with optional hybrid
retrieval (`nomic-embed-text`). No cloud, no API keys.

```
brief + docs ─► 1 Intake ─► 2 Groundability guard ─► 3 Agent generator ─► 4 Eval generator
                (<=5 Qs)     (flag / narrow / block)   (prompt, retrieval,    (>=20 verified cases,
                                                         tools, contract)      dev / hold-out split)
                                                              │                      │
                         7 Honest report  ◄── 6 Critic ─► optimizer ◄── 5 Judge (deterministic + guarded LLM)
                                              classify → targeted fix → re-run (<=3, revert if no gain)
```

## Results of the two committed demo runs (`runs/`)

Both ran **unattended** on a GTX 1650 (4 GB) in 11-13 minutes.

| | HR policy assistant | Ship-spares procurement assistant |
|---|---|---|
| Documents | 3 policy PDFs | catalogue CSV + 2 PDFs |
| Brief asks for | leave, hours, conduct, travel **+ health insurance & pensions** | catalogue lookup, supplier terms, order cost, approvals |
| Groundability guard | **WARN**: removed *health insurance* and *pension contributions* (not in the documents) -> they became refusals | OK (10/10 topics supported) |
| Tools attached | none (correct: no evidence for any) | `csv_lookup`, `calculator` (no weather, no date) |
| Retrieval | hybrid BM25 + nomic-embed-text | hybrid BM25 + nomic-embed-text |
| Eval set | 21 verified cases | 21 verified cases |
| Final pass rate | **100%** (21/21; 95% interval 85-100%), dev 100%, hold-out 100% | **95%** (20/21; 77-99%), dev 93%, hold-out 100% |
| Judge reliability (known-answer canaries) | 0.83 | 0.92 |
| Run status | succeeded with warnings | succeeded with warnings |

**Read these numbers with care** (the reports say the same):
* 21 cases: one case moves the score 5 points. The eval set is generated by a small model from the same documents - it is a
  *regression signal*, not a guarantee.
* In these final runs the generated agents already passed the dev split at baseline, so the optimizer had nothing to fix.
  During development the loop did act (an earlier HR run went 77% -> 91% over two accepted iterations, and a combined patch that
  regressed was reverted and retried per category), but those intermediate runs are not committed.
* The one remaining ship-spares failure (`amb-01`) is a *judge* strictness issue: the answer is correct, but the model paraphrased
  its evidence quote of a CSV row, so the verbatim-quote grounding check failed. It is reported as a failure rather than hidden.
* Retrieval benchmark (17 deliberately paraphrased questions, top-4): BM25 9/12 -> hybrid **11/12** (HR), 3/5 -> **5/5** (ship).
  The offline hashing embedder alone gave no gain (13/14 vs 13/14), so hybrid only switches on when a neural embedder is installed.

Open `runs/<name>/REPORT.md` for the full story: run health, groundability, tool decisions with reasons, per-iteration
scorecard, change log (what / why / which failures / score before -> after), every remaining failure with its diagnosis,
and why the numbers can or cannot be trusted.

## Quick start

```powershell
pip install -r requirements.txt
ollama pull qwen2.5:3b-instruct
ollama pull nomic-embed-text                     # optional: enables hybrid retrieval (auto-detected)
python demos/build_demo_docs.py                  # (re)builds the demo PDFs from demos/*/sources
python -m forgeai build --brief-file demos/hr_policy/brief.txt --docs demos/hr_policy/docs --out runs/hr_policy --answers demos/hr_policy/answers.json
python -m forgeai chat runs/hr_policy/agent_definition.json      # generic chat runner: loads ANY produced definition
python -m forgeai ui                             # Streamlit UI: build, browse reports, chat
python -m forgeai serve                          # REST API on :8000 (set FORGEAI_API_KEY to require X-API-Key)
python -m pytest tests -q                        # 64 offline tests (scripted model, no Ollama needed)
```

**Unseen brief (review mode)**, fully unattended - unanswered clarifying questions become recorded assumptions:

```powershell
python -m forgeai build --brief "..." --docs path\to\folder --out runs\review
```
Flags: `--interactive` (answer the <=5 questions in the terminal) | `--approve` (human checkpoint on the requirements) |
`--resume` (continue an interrupted run) | `--judge-model` (separate judge model) | `--embed-model` | `--fallback-model` |
`--max-calls/--max-minutes` (budget) | `--force` (generate even if the guard says BLOCKED).
Exit codes: 0 ok, 2 blocked by the guard, 3 bad input, 4 model unavailable, 5 budget exhausted, 130 interrupted.

## What each requirement maps to

| # | Requirement | Where | How it is made trustworthy |
|---|---|---|---|
| 1 | Intake interviewer | `intake.py`, `prompts/intake_questions.txt`, `requirements.txt` | 5-question cap enforced in code; unanswered questions become *recorded assumptions*; escalation text is sanitised to a contact. |
| 2 | Groundability guard | `groundability.py` | Per topic: lexical coverage + a deterministic evidence sentence + an LLM verdict whose quote is verified verbatim. A timid model cannot veto a covered topic; a lying one cannot invent support. Unsupported topics are cut, listed as known gaps and become refusals; nothing supportable -> `BLOCKED`. |
| 3 | Agent generator | `generator.py` | Declarative JSON (`forgeai.agent/1`), schema-validated. Tools need deterministic evidence in the brief (an HR agent cannot get a weather tool); every decision is logged with reasons. |
| 4 | Eval generator | `evalgen.py`, `prompts/evalgen_*.txt` | Generated, not hand-written. Facts must be verbatim in the source *and* in the reference answer, and relevant to the question; trivial or malformed candidates are rejected (counted in the report). Answerable, ambiguous (informal paraphrase), multi-document, near-miss, off-topic/injection. Dev / hold-out split. |
| 5 | Judge | `judge.py` | Deterministic checks first (facts, numbers in context, evidence quotes, citations). LLM judge is pointwise, per-fact, needs a *verified* quote, and is calibrated with known-answer canaries (gold / wrong / padded-wrong / altered-number / fact-order swap) - see the module docstring for position, self-preference and verbosity bias. |
| 6 | Critic-optimizer | `optimizer.py` | Failures classified as retrieval_miss / prompt_defect / hallucination / wrong_refusal (+ system_error, never "fixed"); single-parameter or single-rule patches; accepted only if dev pass-rate strictly improves, else reverted and retried one category at a time; max 3; everything logged. |
| 7 | Honest reporting | `report.py` | Assembled from measurements by code (no model prose): scorecard per iteration, dev vs hold-out gap, Wilson interval, every remaining failure, judge reliability, eval rejection stats, run health. |
| 8 | Runnable product | `runner.py` | `forgeai chat <definition.json>`; BM25 or hybrid retrieval, compound-question retrieval, tool loop, JSON output contract with code-side citation repair (flagged, counted). |
| 9 | Two demos | `runs/hr_policy`, `runs/ship_spares` | Full artifacts committed: requirements, groundability, definitions, eval sets, calibration, iteration logs, scorecards, reports, every prompt and response (`llm_trace.jsonl`). |

Stretch goals implemented: **human checkpoint** (`--approve`), **budget enforcement** (calls / minutes), **Streamlit UI + REST API**.
Not done: prompt tournament, factory-vs-hand-written baseline, regression mode, hosting.

## Production hardening (why it should not fall over)
* **Typed errors** (`errors.py`) with fix hints and exit codes; **pydantic schemas** (`schemas.py`) on every model reply and stage artifact.
* **Resilient model client** (`llm.py`): retries with backoff, fallback models, circuit breaker, preflight ("model not installed -> run `ollama pull ...`"), over-long prompts shrunk not silently cut, invalid JSON re-asked with the exact error.
* **Resumable**: stage checkpoints keyed by input hashes + per-case evaluation cache; `run_status.json` rewritten after every stage; atomic, Windows-safe writes (`fsutil.py`).
* **Robust ingestion** (`docs.py`): corrupt / empty / duplicate / encrypted / oversized files are skipped and reported; PDF, DOCX (incl. tables), XLSX, CSV, HTML, TXT/MD; encodings fall back.
* **Chaos tests** (`tests/test_reliability.py`): random model faults, garbage output, crash-then-resume, budget stops, hostile questions, malformed tool arguments. They caught real bugs (ignored budget, swallowed outages, a Windows file-replace race).
* **API** (`service.py`): job queue, upload validation, path-traversal protection, optional API key, restart recovery.

## Honest limitations
* A 3B model writes the eval set, the agent's answers and (by default) the judge: shared blind spots and self-preference are possible. Use `--judge-model` with a larger model for a stronger judge.
* "No errors" is not achievable with LLMs; the goal is *no silent errors*: failures are typed, explained, recorded, and quality is measured.
* Scanned/image-only PDFs are detected and reported but not OCR'd. Eval sets are small (about 21 cases) on small documents.
* Near-miss and multi-doc questions are partly constructed deterministically (the small model writes them poorly); this is labelled in each case.
